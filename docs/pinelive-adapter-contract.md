# Pinery market-data and pinelive Broker adapter contracts

Market data adapters belong to `@heyphat/pinery`; execution adapters belong to `@heyphat/pinelive`. A broker must not expose history or live-bar methods, and pinelive must not implement venue data recovery.

## MarketDataProvider

A live provider preserves `HistoryProvider` compatibility and adds strict `resolve`, resolved-only `historyResolved`, `closedBars({ after, signal })`, and optional `disconnect`. `ResolvedDataInstrument` includes strategy symbol, opaque provider handle, exact venue symbol, tick size, quantity step, minimum order quantity, and available point-value/exchange/expiry metadata.

Providers emit valid unix-second bars that are closed, ascending and unique. `after` is exclusive. Polling adapters intentionally overlap the previous timestamp, suppress duplicates, backfill every returned missed bar, and own retry/reconnect policy. Failures are redacted `MarketDataError` values classified as connectivity, auth, rate-limit, invalid-symbol, entitlement, or malformed-data. Cancellation must stop waits and in-flight transport calls where supported.

Node-only filesystem/profile/SDK construction belongs behind `@heyphat/pinery/node`. Wrappers must preserve the complete live surface, lifecycle, `assetClass`, and stable non-secret cache identity or reject live wrapping. History and instrument caches must partition distinct configured sources without exposing identity text in filenames. A historical-only provider must fail clearly when selected for a live run.

Tiger market data uses `TigerMarketDataTransport`. The provider freezes one exact futures contract and requires authoritative venue finality or server time. Historical and live requests drain opaque older-page cursors; history keeps paging when an unclosed tail would otherwise underfill `limit`, and live polling finishes the complete gap before yielding buffered bars. Cancellation is checked before requests and between those yields.

The Node entry defaults to an official Tiger TypeScript SDK adapter and keeps registration as an override. Intraday futures K-line timestamps are bar opens and are used unchanged; daily and longer periods are refused because the venue stamps them with a session-close boundary that no fixed offset maps to a session open. The newest returned bar is the one still forming, so it is withheld until a later bar appears. Cursors are opaque and replay the first page's parameters verbatim, since the venue rejects a paged request whose other parameters changed. Because SDK HTTP methods expose no `AbortSignal`, cancellation checkpoints surround calls but cannot interrupt one in flight. These limitations must remain explicit.

## Broker

`Broker` in `@heyphat/pinelive` is the normative interface. Every future broker integration implements exactly this surface — venue SDK details stay behind the adapter's own transport seam and never leak into the protocol.

### Required — a broker is not usable without these

| Member                         | Obligation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                           | Stable string identifying the adapter. Appears in ledger binding records.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `capabilities()`               | Truthful declaration. See the capability table below; conformance rejects a declaration that disagrees with the implemented surface.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `instrument(executionSymbol)`  | Verifies **one exact** venue contract. It must not choose a front month or otherwise reinterpret the symbol. Returns positive quantity/tick/minimum metadata plus optional point value, exchange, expiry.                                                                                                                                                                                                                                                                                                                                                                         |
| `getPosition(executionSymbol)` | Signed net strategy-native exposure: long positive, short negative, flat zero. A read failure must raise, never report flat.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `getAccount()`                 | Currency, balance, equity, optional available funds.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `submit(order)`                | At most one market or limit correction per call. A limit requires a positive, instrument-tick-aligned `limitPrice`. Returns a terminal native-unit fill and must never execute a limit at a worse price. Deduplicates the complete economics by deterministic `clientId` for the adapter's lifetime. A timeout after transmission must query the same id before any new order—never retransmit. A working partial fill is polled under that id and never cached as terminal; the venue must explicitly report the remainder cancelled before a terminal partial fill is returned. |
| `flatten(executionSymbol)`     | Reaches zero exposure using the same exact contract and idempotency rules. Operation ids must be collision-resistant across process restarts.                                                                                                                                                                                                                                                                                                                                                                                                                                     |

### Optional — implement only if the venue supports it, and declare it

| Member                       | Obligation                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `connect()` / `disconnect()` | Repeat-safe. `connect` verifies the configured account is the one returned.                                                                                                                                                                                                                                                                                                                                                                                         |
| `cancel(clientId)`           | Addressed by pinelive's client id, not a venue order id. A cancel is a **request, never a guarantee**: the adapter must re-read the order afterwards and let that read decide. A fill that beat the cancel resolves as `filled`, not an error; an unknown id resolves as `not-found`; an order still working afterwards raises a retryable timeout. Gated by arming exactly like `submit` and `flatten`. Required whenever `capabilities().supportsCancel` is true. |

### Capability declaration

`Capabilities` is how callers learn what an adapter can do without probing it, so each field must be accurate:

| Field                   | Meaning                                                                                                                                                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `positionModel`         | `netting` or `hedging`. Hedging adapters must expose opposing positions to the conformance harness.                                                                                 |
| `orderTypes`            | Non-empty and must include `market`; include `limit` only when `submit` validates and preserves `limitPrice` through lookup, idempotency, fill, cancellation, and restart recovery. |
| `supportsNativeFlatten` | Whether the venue closes exposure directly rather than via an offsetting order.                                                                                                     |
| `fractionalQuantity`    | False for contract-based venues such as futures.                                                                                                                                    |
| `transport`             | `poll` or `stream`.                                                                                                                                                                 |
| `supportsCancel`        | True **only** when `cancel` is implemented. Conformance fails a broker whose declaration and surface disagree.                                                                      |

### Cross-cutting obligations

- Expected failures are classified `BrokerError` values. Credentials and account ids are redacted, and error causes must not retain secret-bearing values.
- Order identity covers symbol, side, quantity, type, and requested limit price. Every deterministic client-id component must be framed injectively; lossy character replacement and delimiter-only joining are forbidden. Reusing a client id with different economics is a non-retryable precondition failure. Quantity and limit price are validated against the exact bound instrument before transmission.
- Every in-flight method accepts an `AbortSignal` and checks it before any order-creating step.
- Real adapters receive `armed`. `submit`, `flatten`, and `cancel` each fail independently with a non-retryable precondition while unarmed, even if a caller bypasses CLI/registry checks.
- A broker must not expose history or live-bar methods; market data belongs to pinery.

### Reference implementations

`PaperBroker` declares market and immediately marketable limit support, rejects off-step direct quantities rather than silently snapping them, and never creates an unobservable resting order. Paper and Tiger both implement flatten through an offsetting market order and therefore declare `supportsNativeFlatten: false`. `TigerBroker` advertises limit support only when its transport implements `submitLimit`, and exposes `cancel` only when the transport can cancel. Tiger limit submission additionally requires `cancelStuckOrders: true`: after the poll budget it requests cancellation, polls for terminal settlement, and blocks different client ids while any transmitted order remains unresolved. Emergency flatten remains market-only.

## Binding and safety

Pinelive compares provider and broker symbols, tick size, quantity step, minimum order and point value before warmup reconciliation or any order. The immutable `RunInstrumentBinding` and client ids preserve strategy and execution identities.

Real adapters receive `armed`. `submit`, `flatten`, and `cancel` each independently fail with a non-retryable precondition while unarmed, even if a caller bypasses CLI/registry checks. Shutdown never flattens. Futures contract changes require a stopped run and reviewed exposure migration; automatic rolling is deferred.

## Conformance

Use `runBrokerConformance()` from `@heyphat/pinelive/testing` with a controllable transport. It is the enforcement mechanism for the baseline Broker contract above: every new integration must pass it before being wired into a run. It covers noop/open/add/reduce/close/flip, rejection, market-order idempotency, restart/capped progression, and capability-declaration honesty (`supportsCancel` matching the implemented surface, a non-empty `orderTypes` including `market`). An adapter that advertises `limit` must additionally verify tick/price validation, same-id/different-price rejection, no-worse-than-limit fills, terminal cancellation of remainders, and unresolved-order suppression in its adapter suite. Adapter tests must also cover auth/connectivity/unknown outcomes, cancellation, exact-symbol metadata mismatch, unarmed submit/flatten/cancel, and redaction.

TigerBroker passes this harness through its injected transport. The Node entry defaults to the official Tiger TypeScript SDK adapter, with offline-only facade coverage for account/contract/position mapping, deterministic hashed `userMark` lookup, official working/partial/terminal statuses, scaled quantities, int64 ids, eventual polling, cancellation checkpoints, and same-process ambiguous-submission no-retransmit behavior. `userMark` is not a server-enforced idempotency key and the pending marker is not durable across crashes. Credentialed quote/history and demo-order validation plus durable armed-restart/stale-contract preflight remain unresolved; the integration must not be represented as sandbox- or production-approved.
